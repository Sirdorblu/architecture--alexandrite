## 1. Мотивация
После открытия API для внешних партнеров нагрузка на систему стала непредсказуемой.Яндекс.Метрика показывает только клиентскую часть,но не состояние серверов,очередей и баз данных.Внедрение серверного мониторинга позволит:
*   Узнавать об ошибках раньше клиентов
*   Видеть реальную пропускную способность и задержки
*   Предотвращать падения из-за нехватки ресурсов

## 2. Выбор подхода к мониторингу
Для HTTP API сервисов я выбираю подход **RED** ,так как он идеально подходит для сервисов,обрабатывающих запросы пользователей.
Для инфраструктурных компонентов будет использоваться классический ресурсный мониторинг

## 3. Выбор метрик

Ниже представлены ключевые метрики, которые необходимо собирать в первую очередь

### Группа: API 
*Почему:* Показывает качество обслуживания клиентов

1.  **Number of requests (RPS) for [Shop/CRM/MES] API**
    *   *Зачем:* Понимать нагрузку. Резкий рост может указывать на DDoS или маркетинговую активность
    *   *Ярлыки:* `method` (GET/POST), `endpoint` (/orders, /auth), `status_code` (200, 4xx, 5xx)
2.  **Response time (latency) for [Shop/CRM/MES] API**
    *   *Зачем:* Жалобы на ормоза. Нужно видеть p95 и p99 latency
    *   *Ярлыки:* `endpoint`
3.  **Number of HTTP 500 for [Shop/CRM/MES] API**
    *   *Зачем:* Критический показатель здоровья сервиса
    *   *Ярлыки:* `endpoint`

### Группа: Инфраструктура и Ресурсы
*Почему:* Предотвращение отказов железа.

4.  **CPU % / Memory Utilisation for [Shop/CRM/MES] API**
    *   *Зачем:* Понимать, когда нужно масштабировать 
    *   *Ярлыки:* `instance_id`.
5.  **Number of connections for [Shop/MES] db instance**
    *   *Зачем:* Утечка соединений может положить базу.

### Группа: RabbitMQ
*Почему:* Критическое звено обмена данными.

6.  **Number of message in flight / Ready**
    *   *Зачем:* Если число сообщений растет, значит консьюмеры не справляются
    *   *Ярлыки:* `queue_name`
7.  **Number of dead-letter-exchange letters**
    *   *Зачем:* Индикатор потерянных заказов, которые не смогли обработаться

## 5. Дополнительное задание: Насыщенность (Saturation)

Показатели насыщенности это метрики,указывающие на то, что система захлебывается и больше не может принимать работу.

**Выбранные показатели:**
1.  **CPU Load Average > 80% (на протяжении 5 минут).**
    *   *Действие:* Auto-scaling или алерт DevOpsу для ручного анализа
2.  **DB Connections Usage > 90% от `max_connections`.**
    *   *Действие:* Критический алерт (P1).Приложение скоро перестанет работать.Временное решение — увеличить лимит или перезагрузить пул,системное — внедрить PgBouncer
3.  **RabbitMQ Queue Length > 1000 сообщений (для очереди заказов).**
    *   *Действие:* Алерт.Означает,что производство  или CRM лежит или работает медленнее,чем поступают заказы
