
## 1. Анализ и сбор логов
Сейчас логи разбросаны по файловым системам серверов.Требуется агрегация
**Системы для сбора:**
1.  Shop API, CRM API,MES API
2.  Nginx/Ingress Controller 
3.  PostgreSQL,RabbitMQ

**Уровень INFO:**
*   События смены статуса заказа 
*   Ошибки валидации входных данных
*   Факт отправки сообщения в очередь

Уровень **DEBUG** включается только динамически при отладке чтобы не забивать диск.

## 2. Мотивация
Логирование нужно для детального расследования причин ошибок 
**Влияние:**
*   Сокращение времени расследования багов
*   Возможность аудита действий операторов

**Приоритет:** В первую очередь настраиваем логирование для **MES API** и **CRM API**,так как там происходит основная бизнес-логика и ошибки интеграций.

## 3. Предлагаемое решение
Используем стек **ELK (Elasticsearch, Logstash/Fluentd, Kibana)**

*   **Сбор:** Filebeat на серверах собирает логи из stdout/файлов
*   **Буфер/Парсинг:** Logstash структурирует логи 
*   **Хранение:** Elasticsearch
*   **Визуализация:** Kibana

**Безопасность:**
*   **Masking:** На уровне Logstash вырезать номера карт,телефоны,email-адреса
*   **Доступ:** Role Based Access Controlв Kibana 

**Хранение:**
*   Hot storage (SSD):7 дней
*   Warm/Cold storage: 30 дней.Далее архивация в S3

**Анализ и аномалии:**
*   Настроить **ElastAlert** или Kibana Alerting
*   *Правило:* Если количество записей `level:ERROR` превышает 50 за минуту->Алерт в Telegram
*   *DDoS детект:* Если Nginx access logs c одного IP >100 RPS->Алерт

## 4. Дополнительное задание: Критерии выбора

| Критерий | ELK (Elastic Stack) | Graylog | Splunk | Loki (Grafana) |
| :--- | :--- | :--- | :--- | :--- |
| **Лицензия** | Elastic License  GPL v3 | Проприетарная ($$$) | AGPL v3 |
| **Стоимость** | Бесплатно,но ресурсы жрет много | Бесплатно  | Очень дорого | Дешево  |
| **Полнотекстовый поиск** | Отличный | Хороший  | Отличный | Ограниченный  |
| **Визуализация** | Kibana (мощная) | Встроенная | Мощная | Grafana  |
| **Сложность поддержки** | Высокая  | Средняя | Низкая  | Средняя |

**Вывод:** Выбираем ELK,так как он дает как мнимум возможности поиска по JSON-структурам логов и де-факто стандарт ндустрии с хорошей докой.
