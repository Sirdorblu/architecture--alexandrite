
### Существующие проблемы:
1.  **Потеря прозрачности заказов :** Заказы "исчезают" или зависают между системами.Из-за асинхронного общения через RabbitMQ и отсутствия сквозного ID (TraeId) невозможно понять, где именно застрял заказ без ручного разбора логов трех систем
2.  **Низкая производительность ME :** Операторы жалуются на долгую загрузку дашборда заказов.Это блокирует работу производства. Причина тяжелые SQL-запросы к БД при отображении списков с фильтрацией
3.  **Отсутствие наблюдаемости :** Данных Яндекс.Метрики недостаточно для анализа бэкенд-проблем,ошибок 500 и производительности API
4.  **Ручной деплой:** Release и Prod деплоятся вручную.При росте нагрузки и команды это станет узким местом  и источником ошибок

### Потенциальные проблемы:
1.  **Каскадный сбой :** Рост нагрузки на API может положить базы данных,так как сейчас используется всего по одному инстансу на чтение/запись без масштабирования.
2.  **Переполнение очередей:** Если MES не успеет обрабатывать заказы,RabbitMQ может переполниться, что приведет к потере сообщений

## 2. Инициативы для устранения проблем

Список инициатив для стабилизации системы:

1.  **Внедрение распределенного трейсинга:** Покрыть Shop,CRM, MES и RabbitMQ системой OpenTelemetry + Jaeger, чтобы видеть путь каждого заказа.
2.  **Внедрение серверного кеширования в MES:** Снять нагрузку с БД при запросе списка заказов операторами.
3.  **Централизованное логирование:** Сбор логов всех сервисов в одно место для быстрого поиска причин ошибок.
4.  **Внедрение мониторинга :** Настройка Prometheus + Grafana для отслеживания RPS, Latency и ресурсов серверов .
5.  **Автоматизация CI/CD:** Настроить пайплайны для деплоя в Release/Prod.
6.  **Масштабирование БД:** Добавить Read Replicas для PostgreSQL.

## 3. Приоритезация и план

### Целевая архитектура через полгода:
Система с полным циклом наблюдаемости .Операторы MES получают данные мгновенно благодаря кешу. Разработчики видят проблемы API партнеров в реальном времени на дашбордах Grafana. Процесс релизов полностью автоматизирован.

### Топ-3 инициативы на ближайшие полгода:

Если ресурсы ограничены, я выбираю следующие три пункта в порядке важности:

1.  **Внедрение распределенного трейсинга .**
    *   *Почему:* Это тушение пожара. Мы теряем контракты,потому что теряем заказы. Трейсинг даст ответ Где заказ? и позволит спасти репутацию перед крупными партнерами прямо сейчас
2.  **Внедрение серверного кеширования в MES.**
    *   *Почему:* Операторы — это внутренние деньги компании. Если они ждут загрузки страницы,производство стоит. Это быстрая победа с высоким влиянием на бизнес-процесс
3.  **Внедрение мониторинга.**
    *   *Почему:* Мы открыли API.Мы не можем управлять тем, что не измеряем. Без метрик мы не узнаем,когда упремся в потолок ресурсов CPU/Memory, и система упадет целиком
